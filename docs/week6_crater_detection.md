# 第 6 周：撞击坑自动识别（PyTorch U-Net 基线）

这一周把"从 DEM 上自动找出撞击坑"从概念变成一条**可复现的流水线**：
用 Robbins (2018) 目录当标准答案 → 切成 256×256 的样本 → U-Net 学"每个像素是不是坑"
→ 后处理成带经纬度与直径的目录 → 和标准答案比对打分。

配套脚本：`week6_build_crater_labels.py`、`week6_train_unet.py`、
`week6_mask_to_catalog.py`、`week6_ablation.sh`。
单元测试：`tests/test_week6_labels.py`、`tests/test_week6_channels.py`。

---

## 1. 任务定义：为什么做分割，而不是目标检测

| 方案 | 输出 | 用在撞击坑上的问题 |
|---|---|---|
| 目标检测（YOLO / Faster R-CNN） | 矩形框 + 类别 | 坑是圆的，矩形框的宽高有歧义，直径要靠框反推 |
| **语义分割（U-Net）** | 逐像素 0/1 掩膜 | 直径可由**面积**反算（等效圆直径），环形坑缘天然吻合；这正是 DeepMoon 的范式 |

我们选分割，代价是**评价要分两层**（见第 6 节）：像素级 IoU 会被坑缘几个像素的
偏移狠狠惩罚，而科研真正关心的是"这个坑找到了没有"。

## 2. 数据集：样本、标签、划分

### 2.1 标签从哪里来（为什么不人工标注）

标签用 **Robbins (2018) 月球撞击坑数据库**：全球 1,296,796 个坑，官方 zip 96,227,201 字节，
内部 CSV 238 MB。理由有三条：

1. 客观、可复现，任何人下载同一份文件都得到同一份标签；
2. DeepMoon 论文评价自己时也用它，方便横向比较；
3. 人工标注几百个坑的代价远高于收益，而且主观性会成为审稿人的攻击点。

按经纬度框裁剪后：

| 区域 | 范围 | ≥1 km 的坑 |
|---|---|---|
| 训练区 | 340–360°E, 0–20°N | 9,457 |
| 研究区（测试） | 353–359°E, 8–13°N | 535 |

### 2.2 切片（tile）与正负样本

研究区 DEM 是 512 ppd（0.001953°/px，月球上约 59 m）。取 256×256 像素一块 =
0.5°×0.5° ≈ **15.1 km × 15.1 km**，比最大的研究区撞击坑（13.19 km）略大。

| 概念 | 定义 | 我们的数量（limit=400 的实验） |
|---|---|---|
| 正样本 | 有坑心落在块内的切片 | 400 |
| 负样本 | 没有坑心的切片 | 153（取正样本的 0.5 倍） |
| 真值掩膜 | 坑的圆盘（半径 = 目录直径 / 2） | 覆盖研究区 5.50% 面积 |

负样本只取正样本的 0.5 倍，是为了让模型见过"没有坑的地形"（否则精度会崩），
同时不至于让训练被空块淹没。

**只保留直径 ≤ 7 km 的坑**训练。原因很实际：如果坑比切片还大，一整个切片可能
100% 落在坑内部，标签全是 1，模型只能学到"预测 1"，学不到坑缘。这是调试中真实
踩过的坑（第 9.5 条）。

### 2.3 划分：地理划分，而不是随机划分

```text
训练区 340–360°E, 0–20°N（不含研究区）
   ├─ 南半部（< 14°N）  → 训练集  392 切片
   └─ 北半部（≥ 14°N）  → 验证集  161 切片
研究区 Rimae Bode 353–359°E, 8–13°N → 测试集 120 切片（训练时完全没见过）
```

为什么不用随机划分：相邻切片高度相关（同一地貌、同一光照、相邻高程范围），
随机划分会把"几乎一样"的切片同时放进训练集和验证集，验证分数虚高，这叫
**数据泄漏**。按纬度带切开，验证集是模型真的没见过的地形。

### 2.4 归一化：逐切片稳健标准化

每个切片内部做：`x = (z - median(z)) / (IQR(z) / 1.349)`。

- 用 **median/IQR** 而不是 mean/std：太阳系 DEM 常有极端值（沿轨迹跳变、坏点），均值方差会被拉偏；
- 用**逐切片**而不是全局：撞击坑是**局部形态**特征。月球高程从 -9 km 到 +10 km，
  用全局尺度标准化后，局部几十米的起伏会被压成噪声。这一条是调试里最关键的修正（第 9.7 条）。

## 3. 模型：U-Net（1,286,417 参数）

```text
输入 (1, 256, 256)                      ← 1 通道：标准化高程
  enc1  Conv3x3 → BN → ReLU ×2          16 通道  ┐
  ↓ maxpool                             32×32...  │ 跳过连接把每组特征
  enc2  16→32                           32 通道  │ 直接送到解码器对应层
  ↓                                     64×64    │
  enc3  32→64                           64 通道  │
  ↓                                     32×32    │
  enc4  64→128                         128 通道  │
  ↓ (瓶颈)                              16×16    ┘
  dec4  up-conv + concat(enc4) → 64
  dec3  ... → 32
  dec2  ... → 16
  dec1  → 1 通道 logit
输出 (1, 256, 256)                      ← sigmoid 后 >0.5 判为坑
```

跳过连接（skip connection）是 U-Net 的关键：下采样丢失空间细节，跳过连接把
编码器的**高频边界信息**直接送给解码器，坑缘才能对上。参数量的算法：每个
`Conv3x3` 是 `(C_in×9+1)×C_out`，多一个输入通道只给第一层加 16×9 = **144** 个权重
（`tests/test_week6_channels.py` 里把这条写成了测试）。

## 4. 损失函数：BCE + Dice

```text
loss = 0.5 × BCE(logits, y) + 0.5 × (1 - Dice)
Dice = 2|X ∩ Y| / (|X| + |Y|)
```

| 项 | 管什么 | 为什么需要 |
|---|---|---|
| BCE（逐像素交叉熵） | 每个像素判得对不对 | 提供稳定、密集的梯度 |
| Dice | 预测区域与真值区域的**重叠率** | 对类别不平衡不敏感（正类只占 10–20%），优化的是"整体形状重合"而不是"像素多数投票" |

只用 BCE 会怎样：负类像素占 80–90%，模型把整片预测成 0 就能拿到很低的损失，
于是"全部预测无坑"。这就是类别不平衡问题，Dice 项专门治它。
反过来纯 Dice 的梯度在目标很小时不稳，所以两项各半。

训练配置：Adam，lr=1e-3，batch=8，12 轮，CPU（无 GPU）。
训练日志单调下降，没有过拟合迹象：train loss 0.65 → 0.38，val loss 0.78 → 0.43。

## 5. 数据增强与它的陷阱

训练时对每个切片随机做 90°/180°/270° 旋转和 50% 概率的水平翻转。
月球重力场和太阳方位我们在 DEM 里没有显式编码，旋转不会破坏物理意义
（如果用真实影像，太阳方位角会破坏这个假设——这正是第 8 周"光照域偏移"要研究的）。

## 6. 评价：像素级与检测级必须同时报告

### 6.1 像素级（分割质量）

在切片上比较预测掩膜与真值掩膜：

```text
precision = TP / (TP + FP)    recall = TP / (TP + FN)
F1 = 2PR / (P + R)            IoU = TP / (TP + FP + FN)
```

### 6.2 检测级（科研/工程真正关心的）

```text
预测掩膜 → 连通域标记 → 每个连通域按面积算等效直径 → 小于 1 km 的丢掉
         → 与 Robbins 真值贪婪匹配（中心距 < 0.5 × 真值直径 才算命中）
         → 按直径分档统计 P / R / F1
```

### 6.3 为什么两套都要

同一份预测：像素 IoU **0.298**，而检测级 F1 **0.488**，≥5 km 档更是 8/8 全中。
原因：像素 IoU 把"坑缘偏了 3 个像素"当成大量错误，但它不影响"这个坑被发现"。
只报 IoU 会低估方法价值，只报检测 F1 会掩盖边界精度差的问题。**论文里两套都写。**

## 7. 结果（第 6.2–6.4 步，limit=400，与消融实验的 `dem` 行完全同配置）

> **可复现性证据**：先用 `--limit 400` 跑基线，再在消融实验里用同样的种子、
> 同样的 400 个切片重跑一次 `dem`，两次的逐轮损失**完全一致**
> （train 0.6484 / 0.5813 / 0.5355 / 0.4992 …，val 0.7753 / 0.5774 / 0.5469 / 0.5129 …）。
> 这说明流水线是确定性的，也说明下面对比三个输入特征时，分数的差异只能来自特征本身。

### 7.1 像素级

| 数据集 | IoU | P | R | F1 | n 切片 |
|---|---|---|---|---|---|
| 验证（训练区北带 ≥14°N） | 0.266 | 0.381 | 0.470 | 0.421 | 161 |
| **测试（Rimae Bode，从未见过）** | **0.298** | 0.368 | **0.613** | **0.460** | 120 |

测试集分数不低于验证集，说明**地理外推没有崩塌**（模型不只是在背训练区的地形）。

### 7.2 检测级（研究区）

| 直径档 | 真值 | 检出 | 虚警 | P | R | F1 |
|---|---|---|---|---|---|---|
| 1–2 km | 453 | 232 | 265 | 0.467 | 0.512 | 0.488 |
| 2–5 km | 74 | 45 | 82 | 0.354 | 0.608 | 0.448 |
| **≥5 km** | 8 | **8** | **0** | **1.000** | **1.000** | **1.000** |
| 全部 | 535 | 285 | 347 | 0.451 | 0.533 | **0.488** |

连通域：1,263 个原始 → 尺寸过滤（≥1 km）后 632 个 → 匹配上 285 个。

**结论**：大坑几乎完美，1–2 km 档是瓶颈。SLDEM 是 59 m/px，1 km 的坑只有约
17 个像素跨径，坑缘信息本身就所剩无几——这是**数据分辨率的硬约束**，不是模型问题。

精度 0.451 应当理解为**下界**：Robbins 目录在 1–2 km 档本身不完整（月球上小坑
数量巨大且难以全部编目），347 个"虚警"里有一部分很可能是真坑。

## 8. 输入特征消融实验（控制变量法）

### 8.1 方法

只改一个变量：网络能看到几个输入通道。

| 运行 | 输入通道 | 说明 |
|---|---|---|
| `dem` | 高程（逐切片标准化） | 与第 6.2 步相同的基线 |
| `dem+slope` | 高程 + 坡度（°/45 截断到 0–1） | 给模型显式的"陡缓"信息 |
| `dem+slope+shade` | 高程 + 坡度 + 山体阴影（方位 315°、高度角 45°） | 阴影是视觉上最像"坑"的表达 |

其余全部锁死：同一个随机种子（因此**同一批 400 个切片、同一套训练/验证划分**）、
同样 12 轮、同样 lr=1e-3、同样架构。只有这样才能说"分数的变化来自输入特征"。

学术意义：这正是第 8 周"消融实验表"的第一次实践，也是对 H2（多源融合）最小的一次检验。

### 8.2 结果

三次训练共用同一批 400 个切片、同一划分、同 12 轮，只有输入通道不同。
测试集 = Rimae Bode（训练时从未见过）：

**像素级**

| 输入 | IoU | P | R | F1 | ΔF1 | 预测覆盖率 |
|---|---|---|---|---|---|---|
| `dem` | 0.298 | 0.368 | 0.613 | 0.460 | — | 7.24 % |
| `dem+slope` | 0.300 | 0.447 | 0.478 | 0.462 | +0.002 | 4.65 % |
| **`dem+slope+shade`** | **0.377** | **0.628** | 0.486 | **0.548** | **+0.088** | 3.36 % |
| （验证集同序：0.266 / 0.263 / 0.286 IoU） | | | | | | |

**检测级**（同一套后处理参数，只换输入掩膜）

| 模型 | 检测数 | 命中 | 虚警 | P | R | F1 |
|---|---|---|---|---|---|---|
| `dem` | 632 | 285 | 347 | 0.451 | 0.533 | 0.488 |
| `dem+slope+shade` | 310 | 229 | **81** | **0.739** | 0.428 | **0.542** |

分档（`dshade`）：1–2 km P 0.741 / R 0.397 / F1 0.517；2–5 km P 0.700 / R 0.568 / F1 0.627；
≥5 km 7/8（基线是 8/8）。

### 8.3 怎么解读（这是本节真正要学的东西）

1. **F1 几乎不动的是"坡度"**：`dem+slope` 的 F1 只从 0.460 变到 0.462（+0.002，属于噪声级别），
   但 precision 0.368→0.447、recall 0.613→0.478 变化很大。
   **F1 不变 ≠ 模型没变**——它只是把"错杀"换成了"漏检"。只看 F1 会得出"坡度没用"的错误结论。
2. **山体阴影是真正的增益**：IoU +0.079、F1 +0.088，precision 从 0.368 涨到 0.628，
   虚警从 347 个降到 81 个（**4.3 倍**）。原因很直观：阴影是把三维地形"渲染"成
   二维视觉形态，撞击坑在阴影图上就是最典型的亮暗环，正好是卷积网络最擅长识别的东西。
3. **代价是召回下降**（0.613→0.486），而且丢了 8 个大坑中的 1 个。
   对**着陆安全**来说，漏掉一个坑比多标一个假坑危险得多，所以这个权衡不是单向的、
   更不能简单说"新模型更好"。
4. **同一个模型可以调阈值换召回**：现在固定 0.5。把阈值降到 0.3 会把一部分漏检换回来，
   代价是虚警回升。**阈值敏感性分析是下一步（第 8 周）必做的**，它也是 H3（评价不确定性）
   的直接切入点。
5. 结论对 H2（多源融合比单一坡度可靠）是**部分支持**：融合确实改善了识别质量，
   但改善来自"视觉表达"（阴影）而不是"物理量"（坡度）。

## 9. 调试记录：这一周踩过的 8 个坑（最有价值的部分）

> 这些坑都不是"敲错命令"，而是**机器学习流水线里典型的静默错误**——脚本不报错，
> 分数很低，但原因隐蔽。记录下来，后面每个项目都会再遇到。

### 9.1 输入数据读不出来：GDAL 拒绝 VRT 引用原始 IMG

`.vrt` 内层引用了未经 GDAL 处理的 `.IMG`，GDAL 出于安全默认拒绝。
**修法**：`gdal.SetConfigOption("GDAL_VRT_RAWRASTERBAND_ALLOWED_SOURCE", "<repo>/data")`。
**教训**：虚拟数据集（VRT）只是"指针"，指针的另一头也要能被读。

### 9.2 切片窗口差 1 像素并且越界

浮点经纬度转像素时用截断而非四舍五入，边缘切片读出 (257,257) 或越界。
**修法**：`round()` + 边界钳制。**教训**：地理坐标↔像素坐标的取整规则必须显式写死并测试。

### 9.3 归一化用米、训练读千米：输入几乎是常数

SLDEM VRT 存的是**千米**，研究区裁剪件是**米**。脚本按米做统计、按千米喂模型，
输入张量的数值范围错了一位三位，模型看到的是近乎常数的高程。
现象：loss 死活不降。**教训**：**单位必须在函数签名里写死**（`scale_to_m`），
不同来源的同一物理量先统一单位再进流水线。

### 9.4 `--limit` 取"前 N 个"，把验证集抽空了

切片索引按纬度从北往南生成，`[:N]` 截断等于把大部分样本放进**北部的验证带**，
结果 train 24 / val 66，训练样本不够，分数自然崩。
**修法**：改成固定种子下的随机抽样（`rng.choice`）。
**教训**：任何"取前 N 个"的简写都可能隐含空间顺序偏差。

### 9.5 标签里混进了比切片还大的坑

最大坑 13.19 km，切片 15.1 km，部分切片 100% 是坑内部，标签全 1。
**修法**：训练时只保留直径 ≤ 7 km 的坑（保证坑缘落在切片内）。
**教训**：样本尺度和目标尺度必须匹配；"标签全是 1"的样本是毒药。

### 9.6 `pos_weight=10` 用在 16% 的正类上

`pos_weight` 是给类别不平衡用的，正类只占 10–20% 时设 10 会过度惩罚漏检，
训练震荡。**修法**：改回 1.0，把不平衡交给 Dice 项。
**教训**：不平衡处理要按**实测比例**算，不能照抄博客参数。

### 9.7 全局归一化 → 逐切片标准化

见 2.4。全局标准差让局部起伏只占输入动态范围的极小部分，坑的形态被淹没。
**教训**：归一化的尺度应该匹配**你要识别的特征尺度**，而不是数据的全局尺度。

### 9.8 `np.rot90` 把 (C,H,W) 张量转成了 (256,1,256)

支持多通道后，切片张量从 (H,W) 变成 **(C,H,W)**，但 `np.rot90(x, k)` 默认旋转
轴 0 和 1——单通道时 (1,256,256) 被转成 (256,1,256)，`torch.stack` 直接报错；
多通道时它会**静默地**把通道和数据混在一起。
**修法**：`np.rot90(x, k, axes=(1, 2))`、翻转用 `x[:, :, ::-1]`，
并把增强抽成独立函数 `augment_tile()` 供测试调用。
**教训**：数组的**轴语义**（哪一个轴是通道、哪个是行）要在代码里显式表达；
这类 bug 只有在改变通道数时才暴露，所以**每加一个维度就要加一个测试**。

### 9.9 关于"脚本反复返工"的诚实说明

第 6 周确实反复改了几次脚本（多通道支持、增强轴序、损失累加告警）。
根本原因是我们**先写了代码，再验证**。现在的做法改成：
**先跑 1 轮 × 40 切片的冒烟测试**，全链路通了再跑正式实验——
9.8 那个 bug 就是在冒烟测试里抓到的，成本 90 秒，而不是正式跑完 12 轮才发现。

## 10. 与 DeepMoon 的差异（诚实标注，写论文时必须说清）

| 项目 | DeepMoon (Silburt et al. 2019) | 我们 |
|---|---|---|
| 框架 | Keras 1.x / TensorFlow 1.x / Theano | **PyTorch 2.9.1**（重写） |
| 训练数据 | 自己的 512 ppd DEM 切片，k-fold | SLDEM 512 ppd，**地理划分**（南/北/研究区） |
| 标签 | Robbins (2018) | Robbins (2018)（相同） |
| 输出 | 分割掩膜 + 检测器组合 | 分割掩膜 → 连通域 → GeoJSON 目录 |
| 评价 | 像素 + 检测（按直径分档） | 像素 + 检测（按直径分档） |
| 规模 | 多折、数千切片、GPU | 单折、400–1,500 切片、CPU |

所以我们的定位是：**复现范式 + 迁移实现 + 换成地理划分**，不是逐位复现 DeepMoon 的每一个数字。
