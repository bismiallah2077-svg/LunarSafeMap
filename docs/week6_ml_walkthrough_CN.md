# 手把手：机器学习是怎么"学会"找撞击坑的

零基础版。每一步都用**我们自己跑出来的真实数字**，不用抽象例子。
配合 `outputs/week6/train_log.txt`（训练日志）一起读效果最好。

---

## 0. 一句话

机器学习 = **给机器一大堆"题目 + 标准答案"，让它自己调参数，直到答对得越来越多**。
我们要它学的题目是"这块 256×256 的 DEM 里，哪些像素属于撞击坑"。

---

## 1. 样本：机器看到的"题目"

一块切片（tile）= 256×256 个高程值，来自 SLDEM，像元 59.2 m，所以一块切片
覆盖 15.1 km × 15.1 km。

```text
一个样本 = 一个数字矩阵 (256, 256)，每个数 = 该点的高程（米）
          我们是先把它"逐切片标准化"：x = (z - 中位数) / (IQR / 1.349)
          标准化之后，数字大致落在 -2 ~ +2，模型更容易学（第 2.4 节讲了为什么必须这样做）
```

我们这次用了 **400 个含坑的切片 + 153 个不含坑的切片 = 553 个样本**。

---

## 2. 标签：题目附带的"标准答案"

标签（label，也叫真值 / ground truth）也是一张 256×256 的图，但每个像素只有两种值：

```text
1 = 这个像素在某个 Robbins 撞击坑的圆盘里
0 = 不在
```

这就是**语义分割**：不是给图片一个类别（"这是坑"），而是给**每个像素**一个类别。
正类像素只占少数（我们整个研究区约 5.5%，单块切片里约 10–20%），
这个"不平衡"是后面损失函数要专门处理的东西。

---

## 3. 模型：一个带 128 万个"旋钮"的函数

U-Net 就是一个函数 `f(256×256 的图) → 256×256 的概率图`。
它有 **1,286,417 个可调参数**（俗称"旋钮"）。训练开始时旋钮是随机值，
所以输出的全是噪声——这就是为什么第一轮损失很大。

**关键认识**：模型不是"数据库"，它不背答案。它学的是**局部形态**——
撞击坑是碗状负地形，边缘在高程上有特定的梯度模式。这也是为什么验证集
（相邻纬度带）和测试集（完全另一个区域）的分数差不多：它学的是"坑长什么样"，
不是"第 37 号切片长什么样"。

---

## 4. 损失：把"错得多离谱"变成一个数

我们用两项相加：

```text
loss = 0.5 × BCE + 0.5 × (1 - Dice)
```

看我们的真实训练日志（`outputs/week6/train_log.txt`）：

| 轮 (epoch) | 训练损失 | 验证损失 | 说明 |
|---|---|---|---|
| 1 | 0.6484 | 0.7753 | 模型刚初始化，几乎乱猜 |
| 2 | 0.5813 | 0.5774 | 一次性大幅进步 |
| 3 | 0.5355 | 0.5469 | |
| 4 | 0.4992 | 0.5129 | |
| 6 | 0.4522 | 0.4715 | |
| 9 | 0.4032 | 0.4375 | 开始变慢（收益递减） |
| 12 | **0.3819** | **0.4323** | 结束 |

**怎么读这张表**（这是初学者最需要练的）：

1. 两个数都在下降 → 模型在**真的学**，不是碰运气；
2. 验证损失一直**高于**训练损失（0.43 vs 0.38）→ 正常，因为训练时做了随机增强
   且模型见过训练数据；
3. 如果出现"训练损失降、验证损失**升**"，那就是**过拟合**（背答案），我们没有出现；
4. 第 9 轮之后几乎不动 → 再练下去边际收益很小，12 轮够了。想提高，
   要动的是**数据/特征/模型**，不是无脑加轮数。

---

## 5. 梯度下降：怎么"拧旋钮"

每一步（一个 batch = 8 个切片）做四件事：

```text
1. 前向：把 8 块切片喂进网络，得到 8 张预测概率图
2. 算损失：和标签比，得到一个数（比如 0.55）
3. 反向传播：算出"每个旋钮往哪个方向拧能让损失变小"（梯度）
4. 更新：按学习率 lr = 1e-3 的步长拧一点点
```

把 553 个样本全部过一遍叫**一个 epoch**。我们跑 12 个 epoch，一共更新了
12 × (553/8) ≈ 830 次旋钮。CPU 上总共约 13 分钟。

---

## 6. 三个数据集：为什么必须分开

```text
训练集 392 切片（训练区 340–360°E, 0–14°N）  → 用来拧旋钮
验证集 161 切片（训练区 14–20°N）             → 用来看"学得怎么样"，调超参数
测试集 120 切片（研究区 Rimae Bode 8–13°N）   → 只在最后用一次，代表真实成绩
```

**为什么不能随机划分 553 个切片**：相邻切片地貌几乎一样。随机划分会让
"几乎一模一样的切片"分别出现在训练集和验证集里，验证分数虚高——这叫**数据泄漏**。
我们按**纬度带**切、把研究区整个留出来，验证集和测试集都是模型真没见过的地方。

结果印证了这一点：验证 IoU 0.266，测试 IoU **0.298**，测试甚至更高，
说明模型没有靠"背训练区地形"拿分。

---

## 7. 指标：IoU / P / R / F1 到底在算谁

先把每个像素分成四类：

```text
TP（true positive） 预测是坑，真的是坑    ✅
FP（false positive）预测是坑，其实是背景  ❌ 虚警
FN（false negative）预测是背景，其实是坑  ❌ 漏检
TN（true negative） 预测是背景，真是背景  （通常不报）
```

我们测试集的真实计数：**TP = 209,477，FP = 360,319，FN = 132,401**。代入公式：

```text
precision = TP/(TP+FP) = 209477/(209477+360319) = 0.368   → 说是坑的里面 37% 真是坑
recall    = TP/(TP+FN) = 209477/(209477+132401) = 0.613   → 真的坑里找到了 61%
F1        = 2PR/(P+R)                           = 0.460
IoU       = TP/(TP+FP+FN) = 209477/702197       = 0.298   → 交并比
```

**记住三句话**：

- recall 高、precision 低 → 模型"宁可错杀"（我们的情况）；
- IoU 永远 ≤ F1，因为它同时惩罚 FP 和 FN；
- 只看一个数会骗人：我们的 IoU 只有 0.298，但**≥5 km 的坑 8 个全找到、零虚警**。
  原因是像素 IoU 把"坑缘偏了 3 个像素"算成大错，而科研关心的是"坑找没找到"。
  所以我们**又算了一套检测级指标**（第 8 节）。

---

## 8. 从掩膜到目录：后处理决定了科研可用性

网络输出的是概率图，科研要的是"坑在哪里、多大"：

```text
概率 > 0.5 → 二值掩膜 → 连通域标记（每个连成一片的区域算一个候选）
→ 面积 A → 等效直径 d = 2√(A/π) → 直径 < 1 km 的丢掉（去噪）
→ 与 Robbins 真值匹配：中心距 < 0.5 × 真值直径 才算命中
→ 输出 GeoJSON（lon / lat / diameter）
```

这一步把 1,263 个原始连通域压成 632 个可信候选，再匹配出 285 个真坑。
**后处理参数（阈值 0.5、最小直径 1 km、匹配半径 0.5D）都是人为选择，
论文里必须写清楚**——它们会直接改变 P/R/F1。

---

## 9. 消融实验：怎么知道"哪个改动真的有用"

一次只改一个变量：

| 运行 | 输入 | 变量 |
|---|---|---|
| `dem` | 高程 | 基线 |
| `dem+slope` | 高程 + 坡度 | 多了"陡缓"信息 |
| `dem+slope+shade` | 高程 + 坡度 + 山体阴影 | 多了"视觉明暗"信息 |

其他锁死：同种子（同一批 400 切片）、同 12 轮、同 lr、同架构。
这样分数变化就只能归因于**输入特征**。这就是写论文时"消融实验表"的做法，
也是第 8 周不确定性分析的基础。

**我们跑出来的结果**（测试集 Rimae Bode）：

| 输入 | IoU | P | R | F1 |
|---|---|---|---|---|
| DEM | 0.298 | 0.368 | 0.613 | 0.460 |
| DEM + 坡度 | 0.300 | 0.447 | 0.478 | 0.462 |
| DEM + 坡度 + 阴影 | **0.377** | **0.628** | 0.486 | **0.548** |

盯住第二行看：**F1 几乎没变**（0.460 → 0.462），但 precision 涨了 0.08、
recall 掉了 0.135。如果只报 F1，你会得出"坡度没用"的结论；
实际上它彻底改变了模型的性格——从"宁可错杀"变成"宁可不报"。
**所以消融表必须把 P、R 一起列出来**，这也是审稿人一定会问的。

## 12. 五个常见误解

| 误解 | 事实 |
|---|---|
| "分数低就是模型不行" | 先看数据。59 m/px 的 DEM 里 1 km 的坑只有 17 个像素，信息量本身就不够 |
| "多训几轮就好了" | 第 9 轮之后损失几乎不动。要提升得改**输入/数据/模型** |
| "IoU 0.3 很差" | 像素 IoU 对边缘极敏感；检测级 F1 0.488、大坑 100%，才是任务层面的成绩 |
| "虚警都是模型的错" | 我们的"真值"目录在 1–2 km 档本身不完整，347 个虚警里有真坑 |
| "有 GPU 就能做好" | 我们全程 CPU 13 分钟。瓶颈在**标签质量、分辨率、评价设计**，不在算力 |
